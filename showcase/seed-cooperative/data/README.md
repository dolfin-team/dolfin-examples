# Data

The cooperative's register as the farms send it. Every farm, SIRET and lot is invented; the communes are real
Vercors communes.

| File | Rows | Read by |
|---|---|---|
| `farms.csv` | 15 farms: SIRET, name, commune, date joined | `mappings.dlf`, one `Farm` per row |
| `varieties.csv` | 22 variety records: catalogue code, species (in French), name, region, days to maturity, two tags | one `Variety` per row, IRI from the code |
| `lots.csv` | 60 lots: id, variety code, holder's SIRET, harvest year, amount, unit (`kg`, `g`, `packet`, `bulb`, `tuber`), germination rate | one `Lot` per row, plus one amount mapping per unit |
| `exchanges.xlsx` | 30 exchanges, sheet `Exchanges`: id, date (a date cell), giver's and receiver's SIRET, lot, price in graines (empty for a gift) | one `Exchange` per row |

`exchanges.xlsx` is generated by `../generate_exchanges.py` (`uv run generate_exchanges.py`). The script writes the
same bytes every time: the exchanges are listed in it, and the workbook's creation and modification times and the
zip entries' times are pinned to 2026-06-01. The giver of each exchange is the lot's holder in `lots.csv`.

## Deliberate problems

- **Duplicate variety records.** `TOM-NC` and `TOM-CRIMEE` are both (tomato, "Noire de Crimée"), and `GAR-ROSE`
  and `GAR-LAUTREC` both (garlic, "Rose de Lautrec"): two farms filed the same variety under a new code, with
  the species written `Tomate` / `Ail` instead of `tomate` / `ail` (the `case` table matches either). The
  two-field `Variety` key infers `owl:sameAs` between each pair (query `merged_varieties`). This is not a
  violation, so it stays in the CSV. The duplicates leave their optional region and days to maturity empty: a
  merged variety with two different values would be a violation (`origin_region has two values via key merge`).
- **A germination rate of 1.3**, **a lot harvested in 2027** and **an exchange from a farm to itself** are
  violations. The base package must conform to its own shapes (the showcase harness runs `radeau validate`
  on it), so these rows are not in the CSVs or the workbook: each is a scenario in `../validate/bad/`
  (`germination_over_one.ttl`, `harvest_in_future.ttl`, `self_exchange.ttl`), next to a lot without a
  holder and a lot weighed in metres.

Other things to notice:

- `GV-2023-002` (Soissons beans, 0.55) germinates poorly but is not rare: three farms hold Soissons, so the rule
  `seed_bank_candidate` leaves it alone.
- Three bean lots are weighed in grams (`800`, `1200`, `650`) and the rest in kilograms.
- E006 and E015 have no price: gifts (E015 welcomes the newest member).
- E030's price is 4.5 graines.
